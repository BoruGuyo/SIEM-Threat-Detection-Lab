# Wazuh SIEM & Automated Threat Detection Lab

**Author:** Boru Guyo  
**Focus:** Security Operations (SOC), SIEM, Threat Detection and Threat Intelligence

## Project Overview

This project demonstrates practical cybersecurity skills developed through two hands-on SIEM labs at Moringa School.

The project focuses on using Wazuh for Security Information and Event Management (SIEM), developing custom log decoders and detection rules, and implementing Python-based threat intelligence analysis to identify suspicious network activity.

It is organised into two phases, progressing from SIEM configuration to automated threat detection.

## Project Objectives

- Understand and implement SIEM concepts using Wazuh.
- Deploy a containerised Wazuh environment using Docker Compose.
- Develop custom XML decoders to extract information from security logs.
- Create detection rules to identify suspicious activities.
- Analyse security events using Python.
- Compare network indicators against a JSON threat intelligence feed.
- Generate alerts for suspicious IP addresses, URLs and network ports.

## Phase 1: Introduction to SIEM

**Assessment result: 50/50**

Implemented a Wazuh SIEM lab involving:

- Deployment of Wazuh using Docker Compose.
- Development of custom XML log decoders.
- Creation of custom detection and correlation rules.
- Testing detection configurations against supplied security logs simulating APT29 activity.

**Key deliverables:**
- `decoder.xml`
- `rules.xml`

## Phase 2: Advanced SIEM and Threat Intelligence

**Assessment result: 44/50**

Extended the SIEM work by developing a Python-based threat detection script.

The implementation involved:

- Loading threat intelligence indicators from a JSON file.
- Extracting IP addresses, URLs and port information from security events.
- Comparing extracted indicators against known threat intelligence data.
- Identifying potentially malicious indicators.
- Recording detected threats in an alert output file.

**Key deliverables:**
- `c6m2.py`
- `threat_feed.json`
- `alerts.json` (where generated by the script)
